# AgentPulse Fork Runtime Architecture

## 1. Core Philosophy & Invariants

Sprint 4 introduces **Fork from Here**: durable execution branching from historical agent checkpoints.

> **What a fork is:**
> "Restore a supported recorded execution checkpoint into a compatible host, create a new derived run, apply explicit controlled mutations, and continue execution under a safe execution policy."

### What a fork is NOT:
- ❌ Modifying the original historical run.
- ❌ Rewinding a live production system.
- ❌ Blindly re-executing non-idempotent real-world side effects.
- ❌ Copying a JSON blob and labeling it a branch.
- ❌ Magically jumping into arbitrary uninstrumented application code.

```
Original Run (Immutable Evidence)
  Step 0: Planning (Claude) ──────► Boundary 0
  Step 1: Policy Retrieval ──────► Boundary 1, 2
         │
    [Checkpoint: chk_step_1] (cursor: 3, resume: 2)
         │
         ├───► Apply Controlled Mutation (e.g. override account balance $300 -> $50)
         │
Derived Fork Run (New Execution)
  Step 2: Account Lookup (Tool Override) ──► Boundary 3 (Overridden)
  Step 3: Synthesis (Candidate Model)   ──► Boundary 4 (Diverged Output)
```

## 2. Contracts & Data Model

The fork subsystem is defined by versioned Zod contracts in `lib/core/fork/contracts.ts`:

### ForkPlan (`ap.fork_plan.v1`)
Generated by `buildForkPlan()` during pre-flight evaluation:
- `fork_id`: Unique fork execution identifier.
- `parent_run_id`: The direct ancestor run.
- `root_run_id`: The ultimate root of the execution tree.
- `checkpoint_id`: The historical recovery point.
- `resume_step_index`: The 0-indexed step where execution resumes.
- `boundary_cursor`: The starting index in the boundary sequence.
- `mutations`: Array of declared, validated mutations.
- `dependency_policy`: Rules governing model, retrieval, tool, and side-effect resolution.
- `validation`: Pre-flight verdict (`FORKABLE`, `PARTIALLY_FORKABLE`, `NOT_FORKABLE`).

### Dependency Modes & Safe Offline Policy
The default policy is `SAFE_OFFLINE_FORK`:
```typescript
export const SAFE_OFFLINE_FORK_POLICY: ForkDependencyPolicy = {
  model_mode: "SANDBOXED_CANDIDATE",   // Mock or sandboxed candidate model
  retrieval_mode: "RECORDED",          // Replay recorded embeddings/docs
  tool_mode: "RECORDED",               // Replay recorded tool responses
  side_effect_mode: "DENY",            // Deny live external modifications
  network_allowed: false,              // Global network kill-switch active
  allow_tool_overrides: true,          // Controlled overrides permitted
};
```

### ForkResult (`ap.fork_result.v1`)
Captures the execution outcome:
- `status`: `COMPLETED` | `DIVERGED` | `BLOCKED` | `UNSUPPORTED` | `FAILED`.
- `derived_run_id`: ID of the newly generated child run.
- `restored_state_hash`: Cryptographic proof of the state restored.
- `mutations_applied`: Audit trail of applied mutations with before/after hashes.
- `steps_executed`: Number of new steps run in the child execution.
- `blocked_actions`: Counter of denied network or side-effect attempts.
- `final_output`: The result returned by the resumed host adapter.

## 3. Deterministic Mutation Engine

Mutations allow developers to isolate variables and test counterfactual scenarios:

| Mutation Type | Target / Schema | Behavior & Verification |
| :--- | :--- | :--- |
| `state_patch` | RFC 6902 subset (`replace`, `add`, `remove`) | Applied directly to restored state. Protects internal metadata. Audited with before/after SHA-256 hashes. |
| `tool_result_override` | Tool name + replacement payload | Injected into boundary resolver. Replaces recorded tool output when the matching tool is called. |
| `model_parameters` | `temperature`, `max_tokens`, etc. | Configured on candidate model adapter during post-fork generation. |
| `prompt` | System or user prompt replacement | Intercepts model input boundaries and triggers planned divergence. |

## 4. Resumable Host Adapter Contract

AgentPulse does not claim arbitrary language runtime time-travel. Workflows must implement `ResumableHostAdapter`:

```typescript
export interface ResumableHostAdapter {
  initializeFromCheckpoint(context: {
    state: unknown;
    checkpoint: CheckpointReference;
    resumeStepIndex: number;
    boundaryCursor: number;
  }): Promise<void>;

  executeFrom(context: {
    stepIndex: number;
    state: unknown;
    dependencies: HostAdapterDependencies;
  }): Promise<{
    finalOutput: unknown;
    stepsExecuted: number;
    terminalState: unknown;
  }>;

  finalize(): Promise<void>;
}
```

The host application remains responsible for continuing its logic from `stepIndex` using the restored state and provided dependencies (`callModel`, `callTool`, `callRetrieval`).

## 5. Boundary Resolution with `startCursor`

The `BoundaryResolver` supports execution starting from a historical offset:

```typescript
const resolver = new BoundaryResolver(parentRun, {
  startCursor: checkpoint.boundary_cursor,
  toolOverrides: mutations.toolOverrides
});
```

- **Prefix Isolation**: Historical boundaries prior to `startCursor` are not re-evaluated or replayed.
- **Accurate Substitution Accounting**: Distinguishes historical boundaries from boundaries substituted during the fork execution (`getForkSubstitutedCount()`).
- **Override Matching**: Applied tool overrides take precedence over recorded boundaries for matching tool names.

## 6. Execution Lifecycle

```
[Parent Artifact] ──► buildForkPlan() ──► Verdict: FORKABLE
                            │
              ┌─────────────▼─────────────┐
              │     ForkRuntime.fork()     │
              └─────────────┬─────────────┘
                            │
 1. Guard Activation        ├── NetworkKillSwitch armed (fetch/http/https blocked)
 2. State Restoration       ├── restoreState(checkpoint) + verify SHA-256
 3. Mutation Application    ├── applyMutations() + record before/after hashes
 4. Host Initialization     ├── hostAdapter.initializeFromCheckpoint(...)
 5. Boundary Resolver       ├── new BoundaryResolver(..., { startCursor })
 6. Execution Continuation  ├── hostAdapter.executeFrom(...)
 7. Artifact Synthesis      └── Create child RunArtifact with full lineage linkage
```
